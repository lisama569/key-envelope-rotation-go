# 本地密钥环：加密封装与密钥轮换

一个零外部依赖的 Go 库，用本地内存密钥环（可持久化为 JSON 文件）模拟密钥生命周期，
提供面向接收方的 AEAD 密文封装、解封、多代密钥并存、轮换、吊销与按代清理。

- 算法：AES-256-GCM（`crypto/aes` + `crypto/cipher`），每次封装使用密码学随机 nonce。
- 完整性：头部作为 AEAD 的 AAD，任何对密文或头部的篡改都会导致解封失败。
- 并发安全：所有读写经同一把 `sync.RWMutex` 串行化状态访问；随机数与 AEAD 运算在锁外执行。
- 诊断安全：`Info` / `ListInfos` / `Stats` 只导出元数据，任何外部可见信息都不含密钥材料。

## 快速上手

```go
ring := keyring.New()
k1, _ := ring.Rotate()                    // 生成第 1 代密钥
ct, _ := ring.Seal("alice", []byte("秘密")) // 面向接收方 alice 封装
pt, kid, err := ring.Open("alice", ct)    // 解封；kid 为实际使用的密钥标识
```

## 密文格式（线格式）

```
+--------+-------------+-------------------+--------+------------------+
| "KEN1" | 头长 u16be  | Header JSON (UTF8)| nonce  | 密文(含 16B GCM 标签)|
| 4 字节 | 2 字节      | 头长 字节          | 12 字节 | 剩余全部字节         |
+--------+-------------+-------------------+--------+------------------+
```

- 魔数 `KEN1` 与格式版本：头部 JSON 内 `v=1`。魔数不符 → `unsupported_version`。
- `Header JSON` 字段：
  - `magic`：固定 `"KEN1"`
  - `v`：内容格式版本（当前 `1`）
  - `kid`：封装所用密钥标识（形如 `k-xxxxxxxxxxxxxxxx`）
  - `ns`：nonce 字节数（GCM 标准 12）
  - `rcp`：接收方标识（字符串，调用方语义自定）
- **AAD = `"KEN1" + 头长 + Header JSON` 这段前缀的原始字节**。
  GCM 同时保护主体密文与 AAD：改一个字节、插入一个空白、改 `kid`/`rcp` 都会被识别为篡改。
- 解封时按头部的 `kid` 在环中定位密钥，因此多代密钥无需协商即可自动选择正确密钥；
  不存在“用错误密钥解出错误明文”的情况——找不到密钥或校验不过都会明确报错。

## 密钥生命周期

密钥生命周期细分为三个阶段，诊断信息（`Info`/`ListInfos` 的 `state` 与 `current`
字段，`Stats` 的分阶段计数）可直接看出每把密钥处于哪个阶段：

| 阶段 | 新封装 (`Seal`) | 解封 (`Open`) 其历史密文 |
|------|-----------------|--------------------------|
| `active`（当前生效代，全环至多一把） | 是 | 是 |
| `retained`（保留旧代） | 否（新封装只用当前代） | 是 |
| `revoked`（已吊销） | **否，拒绝** | **否，确定性拒绝（`revoked`）** |
| 已清理（`Prune` 后） | — | **否，确定性拒绝（`pruned`）** |
| 环中从未存在 | — | `unknown_key` |

阶段迁移规则：

- `Rotate()`：生成新的一代（版本号单调递增），置为**当前**（`active`）；
  此前的当前代自动降级为 `retained`，更早的各代保持 `retained` 不变。
- `Revoke(id)`：将指定密钥标记吊销并记录吊销时间（`active`/`retained` → `revoked`）。
  - 吊销的是旧代：当前代不变，新封装照常；该密钥的历史密文此后一律解封失败。
  - 吊销的是当前代：环内不再有当前密钥，新封装返回 `no_current_key`；
    再次 `Rotate()` 后恢复。吊销即“拒绝一切使用”，不区分新旧密文。
- `Prune(id)`：按代清理，见下节。
- 空环（从未轮换）调用 `Seal` 返回 `no_current_key`。

## 按代清理（Prune）

密钥长期频繁轮换时，用 `Prune(id)` 显式清理不再需要的旧代，控制密钥环增长：

- 清理必须显式指定目标标识；**当前生效代不允许清理**（`current_key`），请先轮换再清理。
- 清理不存在的标识返回 `unknown_key`；重复清理同一标识返回 `pruned`（判定稳定）。
- 已吊销的密钥也可清理；清理后其历史密文的判定由 `revoked` 变为 `pruned`。
- 清理后密钥材料从环中移除并留下**墓碑**（标识 + 清理时间）：
  - 用该代封装过的历史密文解封时得到稳定、可解释的 `pruned` 失败，
    不会被报成普通格式错误（`malformed`），也不会与“标识从未存在”（`unknown_key`）混淆；
  - 解封严格按密文头部 `kid` 定位密钥，不存在误用其他密钥解出内容的可能。
- 清理与封装、解封、轮换可并发进行：状态由同一把锁串行化，任何时刻不会出现
  状态撕裂，也不会抽走正在生效的当前代。
- 清理前后可用 `Stats()` 查看各阶段数量（`total`/`active`/`retained`/`revoked`/`pruned`），
  确认还剩多少代被保留。
- 墓碑随快照持久化，重载后清理判定依然稳定（仍为 `pruned` 而非 `unknown_key`）。

## 失败原因码（可区分、可归类）

错误为 `*keyring.Error`，可通过 `errors.As` 读取 `Reason`，或用 `errors.Is` 与哨兵比较：

| Reason | 触发场景 |
|--------|----------|
| `malformed` | 密文截断、长度字段越界、头部 JSON 无法解析、nonce 长度与算法不符 |
| `unsupported_version` | 魔数不符或头部版本不受支持 |
| `unknown_key` | 密文 `kid` 在环中不存在；吊销不存在的标识 |
| `revoked` | 使用已吊销密钥进行新封装之外的任何密钥使用（解封历史密文等） |
| `tampered` | AEAD 校验失败：密文主体、标签或受保护头部被篡改 |
| `no_current_key` | 空环或当前密钥已吊销时调用 `Seal` |
| `recipient_mismatch` | 解封接收方与密文头部 `rcp` 不一致（常量时间比较） |
| `pruned` | 密文 `kid` 对应密钥已按代清理；或重复清理同一标识 |
| `current_key` | 试图清理当前正在生效的密钥 |

任意失败路径都不会返回明文。

## 持久化

```go
_ = ring.SaveToFile("var/lib/keys/ring.json")         // 上级目录不存在会自动创建
restored, _ := keyring.LoadKeyRingFromFile("var/lib/keys/ring.json")
data, _ := ring.ExportState()                          // 含材料的完整快照（仅本地落盘/迁移用）
```

- 快照为 JSON，包含每代密钥的标识、版本、阶段（`active`/`retained`/`revoked`）、
  时间戳与密钥材料，以及已清理密钥的墓碑列表；重载后多代并存、当前指针、
  吊销状态、清理判定（`pruned`）全部原样恢复，行为与重载前一致。
- **崩溃安全**：先写同目录临时文件并 `fsync`，再 `rename` 原子替换，最后 `fsync`
  目录。替换失败（如目标被占用、目录只读）时原有文件保持可用、内容不被破坏；
  状态文件权限固定为 `0600`。
- **兼容范围**：旧版快照（无 `retained` 阶段、无 `pruned` 字段）继续可读——
  旧格式中所有未吊销密钥都记为 `active`，加载时仅当前指针指向的密钥保持
  `active`，其余按新语义自动判定为 `retained`；缺少 `pruned` 字段视为无清理记录。
- **矛盾拒绝**：自相矛盾或字段冲突的快照以 `malformed` 明确拒绝，且不会把环
  恢复成不自洽状态（加载要么整体生效要么整体拒绝）。包括：当前指针指向
  `retained`/`revoked`/已清理/不存在的密钥、快照内标识重复、密钥与墓碑冲突、
  未知状态枚举、版本计数回退、密钥材料长度非法。
- **安全提示**：快照含密钥材料，应像对待私钥一样保护文件；面向外部诊断请用
  `Info`/`ListInfos`/`Stats`（输出形如 `{"id","version","state","current","created_at","revoked_at"}`，
  无 `key` 字段）。

## 并发保证

- 状态（密钥表、当前指针、版本计数、清理墓碑）由锁保护，任何时刻不存在状态撕裂。
- 每次 `Seal` 独立向 `crypto/rand` 取 12 字节 nonce；测试在 3200 次并发封装下校验
  nonce 全局唯一，不存在随机数重用。
- 解封严格使用密文声明的 `kid` 对应的密钥材料（锁内复制、锁外运算），不存在跨密钥误用。
- 轮换、清理与封解封可并发进行；轮换窗口内仅可能出现可解释的 `no_current_key`
  （空环瞬间），清理窗口内被清理代的密文只会得到成功或 `pruned` 两种确定结果。

## 验证方法

```bash
go test -race -v ./...     # 全量单测（含竞态检测），日志打印输入标识与判定依据
go vet ./...
```

测试覆盖：正常封解封、空环封装、未知密钥、接收方不符、密文主体/头部篡改、
各类畸形输入、多代并存、吊销旧密钥与吊销当前密钥后轮换、吊销未知标识、
阶段迁移（active→retained）与诊断统计、按代清理（当前代保护/未知标识/重复清理/
吊销后清理/清理后 pruned 判定）、并发清理+封解封+轮换（竞态检测）、
上级目录不存在时的保存与重载、保存失败时原文件完好、清理结果与阶段的重载恢复、
旧版快照兼容加载、矛盾快照整体拒绝、持久化往返（权限/状态恢复）、
诊断输出无密钥材料、16 goroutine × 200 轮并发（nonce 唯一性、跨密钥误用检查）。
